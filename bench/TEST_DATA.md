# TauDEM-Test-Data inventory

Source: <https://github.com/dtarb/TauDEM-Test-Data> (shallow clone, commit
`fe776f43b63c`, 2026-07-23). About 1.8 GB checked out. Each case folder has an
`Input/<case>` and a `ReferenceResult/<case>` (the inputs plus expected outputs).
`Input/testall.bat` (Windows, MS-MPI) and `Input/taudem-tests.sh` (BATS, Linux/macOS)
run the same commands; `compare_results.py` compares a test run folder with
ReferenceResult (needs GDAL Python bindings) using an absolute threshold of 0 and,
past that, a relative 1e-6 check at the max-difference cell. It treats a
projection mismatch only as a warning.

The tables below were generated by `python inventory.py --data <TauDEM-Test-Data>`;
rerun it to refresh them. "Tools exercised" is parsed from `testall.bat`.

## Highlights for the Rust port

* **Every test raster is small.** The largest is 3600 x 3600 = 13.0 M cells
  (`MoveOutlets3/p.tif`, int16 D8 directions, EPSG:4326). The largest DEM that
  pitremove/d8flowdir/aread8 run on is `Base/logan.tif`, 985 x 1660 = 1.64 M cells,
  float32, nodata -FLT_MAX, EPSG:26912, stripped and uncompressed. So the test data
  checks correctness only. Large-terrain performance needs `make_dem.py`.
* Cases that matter for **pitremove / d8flowdir / aread8**:

| case | input | size | dtype / nodata | what it stresses |
|---|---|---|---|---|
| Base | logan.tif | 985 x 1660 | float32 / -FLT_MAX | main chain; -4way, -depmask, no-fill d8, outlets (.shp), positional basename naming |
| Base | MED_01_01.tif | 656 x 456 | int16 / **none**, LZW, tiled | integer DEM, compressed, no nodata set |
| Base | LoganVRT/output.vrt, loganIMG/logan.img, loganESRIGRID/logan | 289 x 498 VRT; 985 x 1660 | float32 | non-GeoTIFF input drivers (VRT, HFA, AIG) |
| fts | fs_small.tif | 1021 x 1277 | float32 / **none** | DEM without nodata; positional naming |
| Geographic | enogeo.tif | 715 x 844 | float32 / -FLT_MAX, **geographic** NAD83 (OGC:CRS83) | lat/lon cell sizes in slope / D8 distances |
| gridtypes | logan.tif | 985 x 1660 | float32 | **output** drivers chosen by extension: .img, .sdat, .bil, .bin; unknown ext `.lg` and no ext become `.tif` |
| AreaD8_data | loganp.tif | 985 x 1660 | int16 / -32768 | outlets from shp / sqlite / GeoJSON / FileGDB, -lyrname / -lyrno |
| GDAL_unset_nodata | p.tif + weights.tif | 2628 x 1171 | int16; weights have **no nodata** | -wg weight grid without nodata, -nc; p.tif has a compound (NAD83 + unknown VCS) CRS |
| NoEPSG | ma2_ep.tif | 313 x 400 | int16 / -32768, custom CRS with no EPSG code | CRS passthrough without an EPSG code; outlets; -nc |
| D8flowextreme | loganp.tif + logansa.tif | 985 x 1660 | int16, float32 | d8flowpathextremeup (not in scope yet) |

* **ReferenceResult was produced with a newer GDAL than the GDAL 2.1 that the
  installed TauDEM 5.3.7 Windows build bundles.** See README.md, "C++ vs
  ReferenceResult". The differences are in CRS text, SAGA nodata and GeoJSON layer
  names, not in cell values.
